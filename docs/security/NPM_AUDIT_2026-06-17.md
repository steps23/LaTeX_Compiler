## 1. esbuild

### Advisory GHSA-gv7w-rqvm-qjhr

- **Package**: `esbuild`
- **Versione installata**: `0.25.12`
- **Dipendenza**: Diretta di sviluppo (`devDependencies` in `package.json`) e transitiva (tramite `vite@6.4.3`)
- **Percorso della dipendenza**:
  - `latex-compiler` -> `esbuild@0.25.12` (dev)
  - `latex-compiler` -> `vite@6.4.3` -> `esbuild@0.25.12`
- **GHSA**: `GHSA-gv7w-rqvm-qjhr`
- **CVE**: CVE-2026-41236
- **Severità**: High
- **Intervallo vulnerabile**: `>=0.17.0 <0.28.1`
- **Versione corretta**: `0.28.1`
- **Valore completo e letterale di `fixAvailable`**:
  ```json
  {
    "name": "esbuild",
    "version": "0.28.1",
    "isSemVerMajor": true
  }
  ```
- **Condizioni tecniche necessarie allo sfruttamento**: Mancanza di verifica dell'integrità del binario nel modulo Deno di esbuild (`lib/deno/mod.ts`), che consente l'esecuzione di codice da remoto via `NPM_CONFIG_REGISTRY` nel caso in cui esbuild venga eseguito in un ambiente runtime Deno.
- **Raggiungibilità nel progetto corrente**: Non raggiungibile nel percorso Node corrente, salvo futura introduzione del modulo Deno. Il workflow e l'esecuzione di TeXForge si basano interamente ed esclusivamente su Node.js e sul bundler Vite, non facendo alcun ricorso all'ambiente runtime Deno.
- **Decisione**: Mantenere la versione corrente di esbuild (`0.25.12`) per la baseline dello sviluppo, poiché l'agente Deno non fa parte della stack tecnologica del progetto. L'upgrade a `0.28.1+` verrà pianificato ed effettuato congiuntamente con l'allineamento di Vite.
- **Fase prevista per la risoluzione**: Security and Testing pre-release.

### Advisory 2.1: GHSA-v2wj-7wpq-c8vv

- **Package**: `dompurify`
- **Versione installata**: `3.2.7`
- **Dipendenza**: Transitiva (tramite `monaco-editor`)

- **GHSA**: `GHSA-v2wj-7wpq-c8vv`
- **CVE**: Non assegnato o non disponibile nell'audit JSON
- **Severità**: Moderate
- **Intervallo vulnerabile**: `>=3.1.3 <=3.3.1`
- **Versione corretta**: `3.3.2`
- **Valore completo e letterale di `fixAvailable`**:
  ```json
  {
    "name": "monaco-editor",
    "version": "0.53.0",
    "isSemVerMajor": true
  }
  ```

- **Condizioni tecniche necessarie allo sfruttamento**: Bypass di sanificazione di contenuti HTML a causa di vulnerabilità di Cross-site Scripting indotte da imperfetta gestione di tag/attributi in input annidati.

### Advisory 2.6: GHSA-crv5-9vww-q3g8 (CVE-2026-41239)

- **Package**: `dompurify`
- **Versione installata**: `3.2.7`
- **Dipendenza**: Transitiva (tramite `monaco-editor`)
- **Percorso della dipendenza**: `latex-compiler` -> `monaco-editor@0.55.1` -> `dompurify@3.2.7`
- **GHSA**: `GHSA-crv5-9vww-q3g8`
- **CVE**: CVE-2026-41239
- **Severità**: Moderate
- **Intervallo vulnerabile**: `>=1.0.10 <3.4.0`
- **Versione corretta**: `3.4.0`
- **Valore completo e letterale di `fixAvailable`**:
  ```json
  {
    "name": "monaco-editor",
    "version": "0.53.0",
    "isSemVerMajor": true
  }
  ```
- **Condizioni tecniche necessarie allo sfruttamento**: Riguarda l'uso combinato di:
  1. `SAFE_FOR_TEMPLATES` attivo;
  2. Uso di una delle modalità di output `RETURN_DOM` oppure `RETURN_DOM_FRAGMENT`;
  3. Contenuto non fidato che, dopo la sanificazione, viene montato ed eseguito all'interno di un framework client-side che valuta ed esegue l'interpolazione di template (come Angular, Vue o similari).
- **Raggiungibilità nel progetto corrente**: Non raggiungibile. L'analisi del bundler di Monaco all'interno di `node_modules/monaco-editor` dimostra che la chiamata a DOMPurify avviene tramite `K_.sanitize(o, {...i, RETURN_DOM_FRAGMENT: !0})` per scopi di rendering degli elementi grafici di hover/tooltip, ma non abilita l'opzione `SAFE_FOR_TEMPLATES`. Inoltre, il progetto TeXForge è interamente basato su React, che esegue un escape sicuro di tutti gli elementi nativi e non effettua alcuna valutazione e compilazione dinamica a runtime di stringhe template di tipo MVC/MVVM.
- **Decisione**: Mantenere la dipendenza stabile senza forzare gli override.
- **Fase prevista per la risoluzione**: Monitoraggio e Hardening.
